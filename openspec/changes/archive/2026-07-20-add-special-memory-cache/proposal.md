## Why

当前工具箱缺少一个并发安全、带绝对过期时间且能直接保存字节数据的轻量内存缓存。业务若各自组合 `sync.Map`、过期判断和数据封装，容易产生重复实现及不必要的内存复制，增加 GC 压力。

## What Changes

- 新增 `utils_cache_memory` 内存缓存工具，以全局 `sync.Map` 保存缓存条目。
- 每个条目使用 `[]byte` 表示，前 8 字节编码 Unix 秒级过期时间，其余字节保存业务数据。
- 提供 `Set`、`Get`、`Delete`、`Range` 等并发安全操作，并在读取时返回过期时间与业务数据。
- 约定过期条目不再作为有效缓存返回，并提供清理过期数据的能力。
- 在保证 API 安全性的前提下减少数据封装、读取过程中的重复复制，并通过单元测试和基准测试验证行为。

## Capabilities

### New Capabilities
- `special-memory-cache`: 定义字节数据的并发存取、绝对过期时间编码与读取、过期判定及清理行为。

### Modified Capabilities
- 无。

## Impact

- 在 `utils_cache_memory` 下新增 Go 实现、单元测试和基准测试，并完善现有 `README.md`。
- 新增供业务调用的内存缓存 API；不引入第三方依赖或外部服务。
- 缓存数据仅存在于当前进程内，进程退出后不会持久化。
